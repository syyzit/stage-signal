# OpenCode task complete — issue #45 (doctor-reclaim-45)

## What
- `docs/examples/orchestrator.md`: the DEAD_PID reclaim snippet now calls `fail --reason TEXT --if-dead-pid` instead of plain `fail` (plain `fail` on `running` is IllegalTransition, exit 3). The snippet handles refusal explicitly; live/unknown pid → exit 3, no mutation; doctor stays advisory-only. Docs now match SPEC §Terminal transitions (`fail --reason [--if-dead-pid]`).
- `examples/orchestrator-watchdog.sh`: new opt-in `--doctor-reclaim` flag (default off, backward compatible). When enabled, after the normal snapshot it runs `doctor --json`; only on a `DEAD_PID` warning it calls `fail --reason … --if-dead-pid`. Exit codes: 0 no DEAD_PID, 1 doctor JSON unavailable, 12 reclaim performed, 3 guard refused (live/unknown pid). A `python3`-missing failure exits 1 without attempting reclaim (doctor's liveness itself never raises, so this is defensive parity with the pre-existing `describe()` helper).
- No product code changes, no version bump.

## Why
Fixes the dogfood gap from PR #42: the orchestrator guide reclaimed a dead runner with plain `fail` while state was still `running`, which is an IllegalTransition. The watchdog now offers the same guarded reclaim (#43's `--if-dead-pid`) behind an explicit opt-in so default behavior is unchanged.
